# Result-Contract Fixes: 1 November 2026

## Scope

Base revision: `92a3682424ddbb1b15a9a4e060f80c3749526ad9`.

Downstream fMRI analyses with DeTime 0.1.3 reported six problems in the VMD,
EMD, and MVMD wrappers. Each report was first written as a regression test on
a synthetic signal with a known answer and run against the base revision.
Only reports that the tests reproduced led to code changes.

| Report | On the base revision | Change | Regression test |
|---|---|---|---|
| VMD centre frequencies off by 2π | Reproduced on both backends | Unit corrected | `test_vmd_center_frequencies_are_in_sampling_frequency_units` |
| VMD fails on odd-length input | Reproduced on both backends | One-sample padding | `test_vmd_accepts_odd_length_series` |
| EMD does not return its IMFs | Reproduced | `components["imfs"]` added | `test_emd_returns_backend_imfs_in_mode_time_channel_layout`, `test_emd_imfs_match_pyemd_and_reconstruct_the_input` |
| MVMD decomposes along the channel axis | Not reproduced; already fixed by `cb0149d` | None | `test_real_pysdkit_documented_layout_recovers_two_tones_in_every_channel` |
| MVMD centre frequencies are not exposed | Reproduced | `meta["center_frequencies"]` added | `test_real_pysdkit_center_frequencies_are_reported_in_sampling_units` |
| MVMD defaults miss a 0.2 Hz tone | Reproduced; caused by PySDKit's default initialization | Documented; defaults unchanged | `test_mvmd_documented_defaults_reach_the_backend_unchanged` |

The tests are in `tests/wrappers/test_vmd_frequency_and_length.py`,
`tests/wrappers/test_emd_imfs.py`, and
`tests/wrappers/test_mvmd_orientation.py`.

## Changes that affect numerical results

### VMD centre frequencies

Both VMD backends, vmdpy and the native kernel, discretize the mirrored
spectrum as `i / T - 0.5`. Their `omega` is therefore in cycles per sample.
The wrapper multiplied it by `fs / (2π)`, which treats it as radians per
sample. `meta["center_frequencies"]` is now `|omega| * fs`, in cycles per
unit time. This is the unit of `fs` and of `meta["dominant_frequencies"]`.
The documentation did not previously state a unit for this field; the
[API reference](../api.md#decompresult) now does.

For tones at 0.03 and 0.2 Hz sampled at 0.5 Hz, the base revision reported
0.00476 and 0.0318. The corrected values are within 2% of the true
frequencies. **To convert centre frequencies from earlier runs, multiply
them by 2π.** Mode grouping uses the FFT-peak `dominant_frequencies` unless
all of them are zero. Trend and season assignment changes only in that
fallback case.

### VMD odd-length input

vmdpy and the native kernel both drop the final sample of an odd-length
series. The wrapper then failed when it subtracted the shorter modes from the
input. The wrapper now appends one repeat of the final sample, which is the
first sample of VMD's own half-sample-symmetric boundary mirror. It runs the
backend on this even-length series and crops the modes back to the input
length. `meta["padded_samples"]` is 1 for padded input and 0 otherwise.
Even-length results are unchanged.

In 60 random-phase three-tone series of length 401, half of them with added
noise, the median absolute reconstruction error at the final sample was 0.21
with this padding. At the end of the same series truncated to 400 samples, it
was 0.23. Linear extrapolation and reflection of the second-to-last sample
gave similar values, so the simplest rule was kept. These errors are VMD's
usual boundary effect.

### EMD IMFs

The EMD wrapper computed the IMFs but returned only the grouped components.
`result.components["imfs"]` now has shape `(n_imfs, n_samples, 1)`, the layout
CEEMDAN adopted in the [October update](2026-10-29.md). `[..., 0]` recovers
PyEMD's two-dimensional array, whose last row is the residue.
`meta["component_layouts"]` records the layout. Trend, season, and residual
are unchanged.

### MVMD centre frequencies

The MVMD wrapper now requests PySDKit's `return_all` output when the backend
accepts it. It reports the final shared centre frequencies as
`meta["center_frequencies"]`, in the same unit as VMD. The modes are
unchanged. A backend without `return_all` gives the same result as before,
without this key.

## MVMD initialization: documented, not changed

DeTime passes `K=3`, `alpha=2000`, `tau=0`, and no initialization to PySDKit.
PySDKit's defaults therefore apply: `init="zero"` and at most 100 iterations.
DeTime's VMD default is different (`init=1`, uniform).

The check used a six-channel panel of 0.03 and 0.2 Hz tones, 500 samples
long, sampled at 0.5, 1, and 1.39 Hz. With zero initialization and
`alpha=2000`:

- `K=2` put both modes at about 0.03 Hz at all three sampling rates, with 100
  or 500 iterations.
- `K=4` with 100 iterations missed the 0.2 Hz tone at 0.5 and 1 Hz.

PySDKit's uniform initialization recovered both tones in all 12 settings
tested (`K` of 2 and 4, `alpha` of 2000 and 500). Zero initialization with
`alpha=500` recovered them in 5 of 6. `init` is not a public DeTime MVMD
parameter, and this update does not change the defaults. When MVMD modes are
expected to separate distinct rhythms, check `meta["center_frequencies"]`.

## MVMD input layout

The axis report described DeTime 0.1.3. Commit `cb0149d` already sends
PySDKit `(channels, time)`. The new two-tone, six-channel test passes on the
base revision. At `c209d81`, the commit before `cb0149d`, it fails: both modes
come out at 0.03 Hz.

## Method animations

The EMD, VMD, MVMD, and MEMD animations record hashes of the wrapper files
changed here. They were regenerated with

Their numerical source arrays are identical to the previous ones; only the
rendered images, artifact hashes, and render provenance changed. The manifest
now lists the regeneration environment alongside the original one.
