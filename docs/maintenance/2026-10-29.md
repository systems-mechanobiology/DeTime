## Changes that affect numerical reproducibility

### MSTL and Box-Cox

The statsmodels 0.15 implementation creates `est_lmbda=None` for fixed lambda.
The previous fallback treated the presence of that attribute as a usable
estimate. The wrapper now distinguishes an explicitly specified lambda from
an estimated one and implements the zero-lambda logarithm explicitly.
See the [upstream source](https://www.statsmodels.org/stable/_modules/statsmodels/tsa/stl/mstl.html).

For transformed trend `T`, summed seasonal terms `S`, and inverse transform
`g_inv`, the original-scale allocation is:

```text
trend    = g_inv(T)
season   = g_inv(T + S) - g_inv(T)
residual = y - g_inv(T + S)
```

This keeps the public additive reconstruction contract. It defines a combined
seasonal contribution; independently inverting every additive component would
not preserve the same meaning. The wrapper also copies nested `stl_kwargs`
before passing it upstream, so fitting does not mutate the caller's settings.

### CEEMDAN parameters and randomness

The wrapper now forwards `epsilon`, `trials`, the top-level `seed`, and
`n_jobs`. It uses serial PyEMD execution when `n_jobs=1`, which is the default.
With more workers, it supplies an explicit process limit. PyEMD's
[reproducibility guidance](https://pyemd.readthedocs.io/en/latest/ceemdan.html)
requires a fixed noise seed and serial execution; equal seeds alone do not
establish identical results in parallel execution.

`noise_width` previously set an unused attribute on the upstream CEEMDAN
object. It is retained as a warned alias for `epsilon`. **Configurations that
previously supplied `noise_width` now change the actual noise amplitude.**
Reproducing an old run therefore requires the old source revision and recorded
upstream version. New configurations should specify `epsilon` directly.
Passing both parameter names is rejected.

The actual prior upstream defaults were 100 trials and epsilon 0.005; the
registry now documents those values. Raw IMFs are retained in
`result.components['imfs']`, and a mode cannot be included in both the trend
and seasonal groups. Effective seed, noise settings, and parallelism appear in
metadata. Explicit `backend='native'` is rejected for this Python integration.

## Verification commands and compute

From a checkout with the development and optional EMD dependencies installed:

```bash
python -m pip install -e '.[dev,docs,emd]'
python -m pytest tests -q -rs
python scripts/generate_schema_assets.py --check
python scripts/generate_method_cards.py
python scripts/smoke_optional_univariate_backends.py
python scripts/check_doc_consistency.py
mkdocs build --strict --site-dir build/docs-validation
python scripts/check_site_seo.py --site-dir build/docs-validation
```

| Stage | Placement | Purpose |
|---|---|---|
| MSTL and CEEMDAN regressions | Local CPU, serial numerical paths | Check values and configuration against actual upstream implementations |
| Package suite | Local CPU; existing CI covers OS/Python combinations | Protect existing core, wrapper, CLI, and documentation behavior |
| Documentation build | Local CPU or existing GitHub Pages workflow | Check links, generated references, unique metadata, and sitemap |
| Forecasting example | Local CPU | Demonstrate a valid information boundary on one synthetic series |

No GPU or cluster allocation is required for this maintenance pass. Full
cross-package benchmarks, new neural-model training, and GPU experiments are
outside its executed scope. The existing frozen release evidence remains a
separate, dated artifact.
